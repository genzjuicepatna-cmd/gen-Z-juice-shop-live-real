# UI Redesign Plan — "Juice Pop" for Gen Z & Gen Alpha

**Scope:** complete visual + interaction redesign of the **storefront** (customer ordering) and the
**administrative side** (POS, Kitchen, Express, Analytics, Settings, etc.).
**Constraint:** no backend changes — Dexie schema, Supabase migrations, sync engine, auth, printing,
AI and payment services keep their current logic and contracts.
**Decisions locked:** full juice rebrand · bold "juice-pop" design language · admin gets a new token
layer + shell + hand-rebuilt key views, remaining views inherit and get spot fixes.

---

## 1. What we are actually redesigning

This is a hybrid app, and the redesign has to land in **three rendering worlds** that must agree
with each other:

| World | Entry | What it is | Files |
|---|---|---|---|
| **A. Static/SSG marketing** | `src/app/**` | Next.js App Router, statically exported. Crawlers and no-JS visitors only ever see this. | `layout.tsx`, `page.tsx`, `menu/`, `about/`, `offers/`, `catering/`, `support/`, `_components/StorefrontSeoShell.tsx`, `_components/StaticPageChrome.tsx`, `_components/StorefrontJsonLd.tsx` |
| **B. Customer SPA** | `#/self-order` | React, mounted into `#app` by `CustomerView` → `CustomerApp`. Replaces world A on boot. | `src/views/customer/**` (8 components, 1256-line `CustomerApp.tsx`), `src/components/CustomerLoginScreen.tsx` |
| **C. Admin/POS SPA** | all other hashes | Hash router + **class views that build markup with `innerHTML` strings**, not JSX. | `src/main.ts` (1049), `src/router.ts`, `src/components/Sidebar.tsx`, `src/views/{pos,kitchen,express,admin,staff,tables,inventory,customers,channels,analytics,ai,developer}/**` |

**Critical architectural fact:** worlds A and B render *the same storefront content twice* — once as
pre-rendered HTML for SEO, once as the live SPA — and `src/main.ts#hideLoadingScreen` swaps one for
the other. Any storefront redesign must be applied to **both**, or the pre-JS paint and the
post-JS paint will visibly differ (layout shift, brand flash, CLS penalty).

**Second critical fact:** world C's views are string-templated, not component-based. A "component
library" for the admin side means **CSS classes + small HTML builder helpers**, not React
components. Rewriting these into React is out of scope and would be a backend-adjacent risk.

### Styling today

Eight hand-written stylesheets, no framework, ~187 KB uncompressed:

```
variables.css        341 lines   design tokens (dark-first, light + system overrides)
base.css             437         resets, typography, utilities
components-v2.css   1532         buttons, inputs, cards, modals, tables, toasts
layout.css          1422         app chrome, POS/kitchen grids, responsive
sidebar.css          463         admin nav
storefront.css      2944         customer SPA — the largest file in the repo
storefront-static.css 634        SSG storefront + static pages
fonts.css              (generated by scripts/fetch-fonts.js — never hand-edit)
```

The existing token layer is already disciplined: it carries `--color-*-on-surface` (AA-legible as
text) and `--color-*-fill` (AA behind white text) variants with contrast ratios documented in
comments. **The new palette must preserve that discipline** — it is the main reason the current a11y
suite passes.

### Current brand vs. target brand

Everything says **"The Taste — Indo-Chinese, Kumhrar Patna"**: 25 source files, the seeded menu
(Momos / Hakka Noodles / Biryani / Burgers), `restaurantName` in the settings table, the dish
photography in `public/assets/dish-*.jpg`, `the-taste-logo.png`, `the-taste-hero.jpg`, the SEO
metadata, JSON-LD, sitemap, and receipt/invoice/WhatsApp/UPI templates.

## 2. What "100/100" means here — the scorecard

The plan is only finishable if "100/100" is measurable. Two halves:

### 2a. Machine-gradeable (hard gates, must all pass in CI)

| Gate | Target | How it is measured |
|---|---|---|
| Lighthouse Performance (static storefront, mobile) | **100** | `/`, `/menu`, `/offers` |
| Lighthouse Accessibility | **100** | same routes |
| Lighthouse Best Practices | **100** | same routes |
| Lighthouse SEO | **100** | same routes |
| axe-core WCAG 2.1 A/AA | **0 serious, 0 critical** | existing `tests/e2e/accessibility.spec.ts`, extended to every redesigned surface |
| LCP | **< 2.0 s** on mobile 4G | Lighthouse |
| CLS | **< 0.05** | Lighthouse — the SSG→SPA swap is the main risk |
| INP | **< 200 ms** | Lighthouse |
| Contrast | every token pair **≥ 4.5:1** (body) / **3:1** (large + UI) | new `scripts/check-contrast.js`, run in `npm run build` |
| Touch targets | **≥ 44×44 px** on every interactive element at ≤ 768 px | new Playwright assertion sweep |
| CSS budget | **≤ 210 KB** uncompressed total | size check in build |
| `npm run typecheck`, `npm test`, `npm run test:e2e` | green | existing scripts |

### 2b. Gen Z / Gen Alpha product rubric (10 criteria, reviewed per surface)

1. **3-second read** — a first-time visitor knows it is a juice bar and can tap "order" without scrolling.
2. **Thumb-zone first** — every primary action sits in the bottom third on mobile; nothing critical in the top corners.
3. **One-hand ordering** — add-to-cart → checkout in ≤ 4 taps, no keyboard unless paying.
4. **Personality over chrome** — sticker badges, fruit blobs, emoji-native category rail, playful empty states. No enterprise grey.
5. **Motion that confirms** — every tap gets a spring, a haptic and a sound (all already wired via `vibrateDevice`/`playSound` in `utils/helpers`); every one respects `prefers-reduced-motion`.
6. **Gamified loyalty** — visible streaks, XP bar, tier badges, unlock animations. Built on the **existing** `loyaltyPoints`/`tier` fields, no new data.
7. **Build-your-own** — juice customization (size, sweetness, boosters, milk base) as a first-class delightful flow, using the existing item-options data model.
8. **Shareable** — order-success screen is screenshot-worthy; share sheet wired to the existing WhatsApp service.
9. **Instant reorder** — "your usual" surfaces on the home screen from existing order history.
10. **Dark mode is not an afterthought** — both themes are designed, not derived.

Admin side gets its own 5:

1. Zero-training POS — a new hire takes an order without being shown.
2. Kitchen legible **from 2 metres**, in glare, on a greasy screen.
3. Every destructive action is undoable or double-gated.
4. Density toggle — comfortable for tablets, compact for desktop stations.
5. Full keyboard operation for the cashier station.

## 3. The design language — "Juice Pop"

### 3.1 Colour

Light-first for the storefront, dark-first for admin/POS (long shifts, kitchen glare), both driven by
one token file. **The hex values below are the starting proposal; Phase 2 runs every pair through
`check-contrast.js` and adjusts before anything ships.**

**Storefront base (light — "Coconut"):**
```
--bg-primary   #FFF9F0   coconut cream
--bg-surface   #FFFFFF
--bg-secondary #FFF1E2
--text-primary #1B1023   blackcurrant ink
--text-secondary #4A3B57
--text-muted   #6B5B78
```

**Admin base (dark — "Night Juice"):**
```
--bg-primary   #120C18
--bg-surface   #1A1122
--bg-secondary #221630
--text-primary #FFF7EC
--text-secondary #C3B4CF
--text-muted   #9A88A8
```

**Fruit accents** — each gets three variants, exactly mirroring the existing `-on-surface` / `-fill`
convention:

| Token | base | `-on-surface` (AA text) | `-fill` (AA behind white) |
|---|---|---|---|
| `--juice-mango` | `#FF9E1B` | `#9A5200` | `#B25E00` |
| `--juice-berry` | `#FF4D8D` | `#B0004A` | `#C1004F` |
| `--juice-lime` | `#7CE04F` | `#2F6B14` | `#35761A` |
| `--juice-blueberry` | `#6C5CE7` | `#4B3BC4` | `#5340D0` |
| `--juice-watermelon` | `#FF5A5F` | `#B01D22` | `#C42227` |

`--color-primary` maps to mango; berry is the secondary/CTA-accent; lime = success/veg; watermelon =
danger; blueberry = info/loyalty. Semantic tokens (`--color-success`, `--color-danger`…) alias the
fruit tokens so **all 20+ admin views restyle without touching their markup**.

Gradients: `--gradient-smoothie` (mango→berry), `--gradient-detox` (lime→mango),
`--gradient-berry-blast` (berry→blueberry). Used for hero, CTA fills and category cards — never
behind body text.

### 3.2 Type

- **Display:** `Bricolage Grotesque` (variable, Google Fonts — quirky, high-personality, still
  legible). New face; add to `scripts/fetch-fonts.js`, latin subset, ~35 KB. This is the only added
  font weight/file.
- **UI / body:** keep `Plus Jakarta Sans` (already self-hosted).
- **Numerics:** keep `Inter` tabular for POS/receipt/analytics alignment (already self-hosted).
- **Fluid scale** replaces the current fixed rem steps:
  `--display-xl: clamp(2.75rem, 8vw, 5.5rem)` … down to `--text-xs: 0.75rem`.
- Headlines run **tight** (`letter-spacing: -0.03em`, `line-height: 0.95`) and **big** — this is
  where most of the Gen-Z read comes from.

### 3.3 Shape & texture

- Radius scale up: `sm 12 / md 18 / lg 28 / xl 40 / full 9999`. Buttons are pills.
- `--radius-blob: 42% 58% 46% 54% / 55% 45% 52% 48%` for fruit/category masks.
- **Sticker badges** — rotated ±3°, hard 2px ink border, offset shadow — for "NEW", "BESTSELLER",
  "0 SUGAR", "VEGAN", streak counts.
- Noise/grain overlay at 2% opacity on hero surfaces (single inline SVG data-URI, no asset cost).
- Glassmorphism is **removed from the storefront** (it costs paint time and reads corporate) and
  **kept, retuned, in admin overlays** where it aids depth.

### 3.4 Motion

Reuse the existing spring curves in `variables.css`, add:
```
--ease-bounce: cubic-bezier(.68,-.55,.27,1.55)
--ease-squish: cubic-bezier(.34,1.56,.64,1)
```
Signature interactions: card squish on press · **fly-to-cart** arc on add · cart badge pop ·
category rail snap · pull-to-refresh juice-drop · number roll-up on totals · confetti + haptic on
order success · streak-flame pulse.

**Non-negotiable:** one `@media (prefers-reduced-motion: reduce)` block disables all of it, and the
existing customer `reduced_motion` preference key (already in `CUSTOMER_PREFERENCE_OPTIONS`) is
wired to the same kill switch.

### 3.5 Voice

Short, lower-case-friendly, second person, zero corporate hedging.
"what are you sipping today?" · "cold. fresh. 6 minutes away." · "you're 2 sips from a free one 🔥"
Applied through `src/content/` only — never hard-coded into components.

## 6. Risks & mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| SSG shell and SPA drift apart visually | CLS penalty, kills Lighthouse 100 | Phase 3 and 4 share the same tokens and are diffed side by side; a Playwright test asserts the pre-JS and post-JS hero occupy the same box |
| `storefront.css` is 2944 lines with unknown dead rules | Regressions in surfaces nobody remembers | Phase 0 baseline screenshots make every regression visible; delete only what the visual diff proves unused |
| Admin views build HTML with `innerHTML` strings | No type safety, easy to break markup | Primitives ship as CSS classes + `utils/ui.ts` builders; XSS discipline preserved via the existing `escapeHtml` |
| CSS grows past budget | Perf score drops | 210 KB gate in build; delete-as-you-go, no parallel old/new systems |
| New display font costs bytes | LCP regression | Single latin variable subset, self-hosted, preloaded, `font-display: swap`; measured in Phase 2 not assumed |
| Heavy motion on low-end Android | Jank, INP failure | Transform/opacity only, no layout-animating properties; `will-change` used sparingly; reduced-motion honoured; tested on the 360 px device |
| Capacitor WebView lags modern CSS | Broken Android build | Avoid bleeding-edge CSS in critical paths; Phase 9 APK smoke test |
| Rebrand breaks tests and SEO | Red CI, ranking loss | Tests updated in the same commit; canonical URLs and route paths unchanged |
| Existing stores keep the old `restaurantName` | Confusing rollout | Documented in release notes; Branding view is the supported change path |
| Scope is genuinely large | Half-finished UI | Phases are independently shippable; the token layer alone already restyles all 20+ admin views |

## 8. Still outstanding after the rebrand

Settled: the store is **Trending Juice** (`src/content/brand.ts`), tagline
"Fresh. Fun. You.", at Sandalpur Road, Kumhrar, Patna. Both come off the
shop's own menu board. Renaming is a one-file change.

Also settled: **the menu is real now.** 25 drinks and 3 combos transcribed
from the board, in its four columns — Juices, Shakes, Special, Combos.

Still placeholder, and each needs a real answer before launch:

1. **Domain.** `STORE_ORIGIN` is `https://trendingjuice.in`, which is **not a
   registered domain**. Every canonical URL, OG tag and the sitemap point at
   it. `public/sitemap.xml` and `public/robots.txt` are now *generated* from
   this constant by `scripts/build-menu-snapshot.js`, so they cannot drift
   from it again — but the domain still has to be bought.
2. **Trademark.** "Trending Juice" is the name on the signage. Availability in
   India has not been checked.
3. **Photography.** All art is generated SVG (`content/categoryArt.ts`). The
   board has real product photos on it — those are the ones to use. Drop files
   into `public/assets/art/` and the build picks them up with no code change;
   `scripts/build-art-manifest.js` prefers `.webp > .png > .jpg > .svg`.
4. **Logo.** `public/assets/store-logo.svg` is a generated mark, not a designed
   identity. The board's lockup (TRENDING in white over JUICE in lime, on
   black) is the thing to reproduce.
5. **Palette.** The board is black, lime green and magenta. The app's tokens
   are mango, pink and lime — close, but the primary accent is mango where the
   board leads with lime. Aligning them means re-running the contrast gate
   across all 84 pairs; not done, and worth a deliberate decision.

### Sizes: two rows per drink

Every drink on the board has a Large and an X Large price. `menuItems` has one
`price` column, the cart carries only a note, and there is no variant model —
so each size is its own row, which is what the schema supports without a
migration. 25 drinks become 50 tiles.

If that grid gets in the way at the counter, the fix is real size variants on
the item — which does mean a schema change on both Dexie and Supabase — not
quietly hiding rows in the seed.

### Old-brand text found after the rename (fixed)

The rename swapped every *display* of the store name, but the previous brand's
**cuisine** survived in fallback expressions, which only surface when a setting
is unset — so nothing looked wrong on a configured install:

- `'Fast Food & Chinese'` was the fallback for `restaurantTagline` in eight
  places, including `services/receipt.ts`. An unset tagline printed it on
  every receipt and invoice.
- `db/seed.ts` did worse than fall back: its migration **wrote**
  `'Chinese Food — Fresh & Reasonable'` into the tagline setting, so a fresh
  PULP install started with a Chinese-food tagline.
- The seed's demo order history was momos, Hakka noodles and chilli paneer, so
  Analytics and the dashboard's "selling fastest" panel reported a menu the
  shop does not serve.
- Admin → Branding's storefront simulator had two hardcoded Indo-Chinese
  dishes and a "🍜 Momos" category tab. It now renders the store's own
  catalogue, which is also the point of a preview.

All now derive from `BRAND` or from the store's own data. The lesson for the
next rename: grep for the old *cuisine and menu*, not just the old *name* —
`|| 'literal'` fallbacks are invisible until a setting is missing.

### Category art was emoji glyphs (fixed)

`public/assets/category-*.svg` were gradients with a single emoji in an SVG
`<text>` node. An emoji in `<text>` renders in whatever emoji font the host
platform has, or as tofu when it has none, so the tile was never reliably the
same picture. The glyphs were also wrong: cold-pressed drew 🧃, a shelf-stable
carton, which is the opposite of what a cold-pressed juice bar sells. Category
art now points at the same drawn cups the per-item art uses.


### The rename found a second layer of leftovers

The first pass caught the old brand's *cuisine* in fallback expressions. The
rename to Trending Juice found more, all in places a configured install never
shows:

- `public/robots.txt` pointed at the previous domain and **nothing generated
  it** — a crawler was handed a sitemap URL on a host that never existed. It
  and `sitemap.xml` are generated from `STORE_ORIGIN` now.
- `scripts/build-menu-snapshot.js` kept its own copy of the origin under a
  "keep in step with brand.ts" comment. A comment is not a mechanism; it reads
  the constant out of `brand.ts` now.
- `src/content/storefront.ts` typed the store name into nine SEO strings —
  exactly what `brand.ts` exists to prevent.
- Settings' invoice preview defaulted to `'Counter 4, Sector 5, Kolkata'`,
  predating even the move to Patna, plus `thetaste.co.in` for email, website
  and UPI ID.
- `getNextOrderNumber()`'s failure path returned a `TT-FALLBACK-` order number.
- `services/whatsapp.ts` advertised `thetaste.co.in` on every shared receipt.

That last file is `// @ts-nocheck`, which is how it also shipped a reference to
an undefined `STORE_ORIGIN` — a runtime `ReferenceError` on every WhatsApp
receipt — without the typecheck saying a word.
